SECURITY

What protects you.
What still depends on you.

Just Zen keeps signed-in websites, Claude and your documents apart from each other and from the rest of your Mac. This page shows the live state of this build, explains each protection, spells out the risks that remain, and gives you direct control over local sessions and data.

01

Websites

  • Every site runs in Chromium's sandbox with Node.js disabled and no bridge into Just Zen, your files or Claude.
  • New apps get their own isolated cookie and storage profile. Shared, Personal and Work profiles share logins only when you choose them.
  • Addresses opened from the URL bar, notes or chat use an in-memory profile that is discarded when the view closes.
  • Camera, microphone, screen capture, native-app launches and other permissions are refused. Saved apps may send notifications only from the address they were saved at.
  • Downloads always go through a native save dialog. Sites with invalid certificates are refused.
02

Encrypted state and app lock

  • Settings, tasks, whiteboard and Claude chat history are encrypted with a key held in the macOS Keychain. Website cookies are encrypted too.
  • Optional Touch ID or passcode lock after inactivity. Passcode attempts back off after three failures.
  • Clear any browser profile, Claude history or all Just Zen data from the controls below.
03

Claude Chat

  • Runs inside Anthropic Sandbox Runtime and macOS Seatbelt. It can read only the workspace you choose plus its own login, and write only where the access mode allows.
  • Uses a Claude login and history owned by Just Zen. Your personal ~/.claude, home folder, other users, external volumes and temporary folders are denied.
  • Network access is limited to Anthropic's servers. Chat refuses to start if the sandbox is not active.
  • Read-only blocks changes at the OS level. Notes-only asks before touching anything other than Markdown and refuses writes through symbolic links. Shell commands, sub-agents and MCP tools always ask first.
04

Claude Terminal and shell

  • Runs with your normal macOS user permissions, exactly like Claude Code in Terminal.app. Just Zen adds no privilege and no sandbox here.
  • Claude Code's own command approval applies. Use Chat when you want enforced Read-only or Notes-only access.
05

Documents

  • PDFs and text render in a separate sandboxed view with no bridge to the main app or Claude, and no network.
  • DOCX and RTF conversion runs in a deny-by-default Seatbelt process with a private temporary folder and no network. Formatted text is reduced to plain allowlisted tags before export.
  • Save copy refuses symbolic and hard links so the original can never be overwritten.
06

App integrity and updates

  • Releases are signed with a Developer ID, notarized by Apple and published with build provenance.
  • The app code ships in a single archive whose integrity is verified at launch. Node.js entry points into the app binary (run-as-node, NODE_OPTIONS, inspector) are disabled.
  • Website favicons are decoded in a sandboxed renderer, never in the main process.
  • Updates are checked 15 seconds after opening and every six hours, downloaded in the background, signature-verified and installed when you quit. Downgrades and pre-releases are refused.
HOW AUTOMATED SECURITY UPDATES WORK

From patch to installed app, without anyone touching it

  • 1. Detection. Dependabot checks weekly for new Electron and dependency versions, waiting three days for patches and seven for larger changes so bad releases surface first. Security advisories trigger a fix immediately.
  • 2. Verification. Each proposed update runs the unit tests, the Seatbelt sandbox test and CodeQL static analysis on a macOS runner.
  • 3. Merge. If everything passes and it is not a major version change, the update is merged, the app version is bumped and tagged. Major versions wait for a human.
  • 4. Release. The tag builds a signed, notarized DMG with provenance attestation and publishes it.
  • 5. Install. Every copy of Just Zen picks it up on next open and installs it on quit.

THE HONEST PART

Risks that remain

  • Prompt injection. A note, document or cloned repository can contain instructions that Claude follows. The access modes bound what that can do; they do not prevent it. Use the narrowest mode that fits.
  • Terminal has your full authority. Anything you approve there runs as you. Use it only for work you would run Claude Code on directly.
  • Browser vulnerabilities. A new Chromium flaw can exist before its patch ships. Sandboxing limits the impact; the automated update chain keeps the window short.
  • Shared profiles. Sites placed in Shared, Personal or Work can see each other's cookies. That is the point of those profiles; use them deliberately.
  • Malware already running as you. It can read the screen, memory and files regardless of Just Zen. The app lock deters casual access to an unattended Mac, nothing more.
  • Phishing. A convincing fake login page inside a web view is as dangerous as in any browser.
  • Compromised release account. Whoever controls the GitHub repository and Apple signing identity controls updates. Keep two-factor authentication on both and share access with no one.
  • No independent audit yet. The review and tests are internal. Do not rely on this for regulated or highly sensitive work without an external assessment.

What you should do

Keep macOS updated and FileVault on. Install updates when Just Zen asks by quitting; that is the whole ritual. Connect only the folders Claude needs and prefer Read-only or Notes-only in Chat. Keep apps isolated unless they need a shared login. Turn on the app lock if the Mac is shared or ever unattended. Keep two-factor authentication on the GitHub and Apple accounts behind the updates.
